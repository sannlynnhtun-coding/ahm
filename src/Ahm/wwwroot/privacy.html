Privacy Policy

Last updated: 30 September 2026

This policy explains how Ahm accesses, uses, stores, shares and protects information when shop owners and authorised staff use its Google Sheets loyalty workspace.

Google user data Ahm accesses

Ahm requests only the Google OAuth drive.file permission. This lets Ahm create Google Sheets files and access files that a user explicitly creates with or selects for Ahm. It does not give Ahm access to every file in the user's Google Drive.

The selected Sheet can contain shop settings, staff labels, reward rules, and customer records entered by the shop, including names, phone numbers, purchase events, stamps, cashback and reward activity.

How Google user data is used

The user's browser reads and updates the selected Google Sheet to provide the visible features the user requests: creating or connecting a shop Sheet, configuring rewards, finding or enrolling members, recording purchases, calculating loyalty balances, and selecting or redeeming rewards.

Google user data is not used for advertising, retargeting, credit decisions, lending, data brokerage, information resale, or any purpose unrelated to Ahm's user-facing loyalty features.

Storage and retention

Shop and customer records remain in the shop-owned Google Sheet. Ahm does not keep a server-side copy of those records. The Google access token remains only in browser memory for the current session and is not written to IndexedDB, LocalStorage, URLs or Ahm application logs.

Ahm may save the selected Sheet ID, public shop ID, staff label, display settings and language preference in the user's browser. It does not save Google access tokens or customer records there. The shop owner controls how long Sheet records are retained and can edit or delete them in Google Sheets. Users can delete Ahm-created files from Google Drive and clear local settings by clearing this site's browser data.

Sharing and disclosure

Ahm does not sell Google user data and does not share it with advertisers, data brokers, information resellers or lenders. The browser sends requests directly to Google APIs to provide the requested features. The hosting/CDN provider may process ordinary website access logs under its own policy, but Ahm does not put Google access tokens or Sheet customer records into those logs.

Anyone whom a shop owner grants Editor access to the selected Google Sheet can view or change that Sheet through Google's services. Shop owners are responsible for granting access only to trusted staff.

Security

Ahm uses HTTPS for data in transit, limits Google access to the drive.file scope, keeps access tokens in short-lived browser memory, and avoids server-side storage of shop and customer Sheet records. No internet service can guarantee absolute security, so shop owners should also protect their Google accounts and review Sheet sharing permissions.

Google API Limited Use and prohibited uses

Ahm's use and transfer of information received from Google APIs complies with the Google API Services User Data Policy, including the Limited Use requirements. Google user data is not used to develop, improve or train generalised or non-personalised AI or machine-learning models. Ahm does not use Google APIs to generate or process non-consensual intimate imagery or any other AI-generated content.

Customer QR links and legacy redirects

A customer QR link contains an identifier only and does not publicly display a name, phone number, balance or rewards. When an older QR link is opened, Ahm briefly reads its encoded value and redirects to the current format without storing the request or customer information or writing it to application logs.

Changes and contact

This policy will be updated before Ahm materially changes how it uses Google user data. For privacy questions, access concerns or deletion requests, contact the developer at sannlynnhtun.developer@gmail.com.
