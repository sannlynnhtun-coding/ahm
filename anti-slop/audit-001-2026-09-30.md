# Anti-slop audit 001

Date: 2026-09-30

Scope: Current Ahm Blazor UI after removal of the Apps Script v2 path. This is an audit only. No UI finding below has been fixed.

Observed product read: a mobile-first shop loyalty tool for non-technical Burmese and English speaking owners and counter staff. The current interface behaves like ENERGY 1 / RHYTHM 1 / MOTION 1, but the repository does not declare these dials or a design direction.

## Findings

1. **HIGH | R-27 | Network work has no visible loading state.** `busy` clears the current message and disables controls, but Google connect, Sheet load, save, member lookup, purchase, reward, and payout operations do not tell the user what is happening. A slow request therefore looks like a frozen screen. Add an operation-specific status such as "Connecting Google" or "Saving purchase", keep it announced with `role="status"`, and prevent duplicate actions without removing context.

2. **HIGH | R-25 | Input placeholder contrast fails WCAG AA.** The rendered placeholder color composites to about `#909997` on white, measured at 2.92:1. Normal text requires 4.5:1. Use a darker placeholder and retain a persistent label so examples remain readable in bright shop environments.

3. **HIGH | R-35 | The connected business flow has no recorded end-to-end click-through.** The build and 16 automated tests pass, and the disconnected routes were inspected at 320 px, 390 px, and desktop widths. The release evidence does not exercise Google authorization, create/select Sheet, member creation, purchase, reward selection, redemption, payout, token expiry, or camera scanning. Add a staging smoke path and record every interactive result before release.

4. **HIGH | R-37 | The product has no declared design direction.** There is no `DESIGN.md`, Design Read, or explicit ENERGY / RHYTHM / MOTION decision, so typography, card treatment, light theme, spacing, and the green palette have no owner-approved rationale. Set direction before any redesign.

5. **HIGH | R-02 | User-facing text contains em dashes.** The static loading homepage, privacy copy, manifest name, generated Sheet title, and related tests or docs use the forbidden character. Replace it with natural punctuation and update the matching test.

6. **MEDIUM | R-06 | Uppercase, wide-tracked labels are used as a default.** Labels such as `GOOGLE SHEETS DIRECT`, `STAFF WORKSPACE`, and the long homepage eyebrow repeat a generic technical style without a written readability or brand reason. Use plain sentence-case labels or document why this voice belongs to Ahm.

7. **MEDIUM | R-12 | Nearly every main surface has the same shadow.** Setup, staff, customer, legal, and homepage sections all use `shadow-sm`, so elevation does not communicate hierarchy. Keep elevation only for the surface that needs foreground priority and leave routine groups flat.

8. **MEDIUM | R-14 | The homepage uses three copy-paste feature cards.** The three equal cards give architecture facts and privacy facts the same visual weight, although they answer different user concerns. Replace them with a short, prioritized explanation tied to the first task, or vary the treatment according to importance.

9. **MEDIUM | R-04 | The member page uses a decorative diamond glyph.** The `◇` mark inside a pale circle does not identify a state or action and matches the generic AI icon pattern. Remove it or replace it with a product-specific mark whose relevance is documented.

10. **LOW | R-20, R-31 | Setup mixes onboarding and ongoing administration on one page.** Connect Google, enter shop details, create a new Sheet, connect an existing Sheet, edit policy, and maintain rewards share one continuous surface. After a shop is connected, the creation choices still remain above the settings form. Split first-time setup from shop settings and show one decision at a time.

11. **LOW | R-15, R-20 | The disconnected staff screen presents the wrong primary action.** With no shop Sheet selected, it shows `Reconnect Google`, a separate `Connect a shop Sheet first` link, and disabled member tools. The one useful next step is setup. Replace the entire blocked workspace with one clear action that takes the user to shop setup, then reveal lookup only when it can work.

12. **LOW | R-16, R-20 | The interface mixes languages and exposes implementation vocabulary.** Burmese mode still shows `Staff`, `Setup`, `Google Sheets direct`, `member token`, `scope`, `drive.file`, `browser memory`, `Reward catalog`, `Active`, and other English or developer-facing terms. English mode also inherits some fixed Burmese and bilingual brand text. Complete both translations and move OAuth detail behind a short "Why Google asks" explanation.

13. **LOW | R-21 | The fixed light theme has no recorded user or brand reason.** Light mode may suit a counter workflow, but the reason is not documented and no theme choice exists. Confirm light-only as an explicit owner decision or implement and verify both themes.

## Verified strengths

- Mobile layout reflows without horizontal overflow at 320 px and 390 px.
- Interactive targets use a 44 px minimum height.
- Keyboard focus is visible, and the skip link appears on focus.
- Main navigation destinations exist.
- Empty member lookup and invalid member link copy provide a next action.
- The green primary button on white measures 8.86:1 contrast.
- The production build and current automated suite pass with no browser console errors on the inspected routes.
